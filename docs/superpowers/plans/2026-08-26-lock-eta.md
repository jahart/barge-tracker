# Lock Traffic ETA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a live-ticking, rough "ETA to OVRC Launch" to each approaching lockage row in the Traffic Log tab's Lock Traffic panel, computed from the lockage timestamp plus an assumed towboat speed — no backend changes.

**Architecture:** Fully client-side, inside `index.html`'s existing `LOCK TRAFFIC` script section. Two pure functions (`estimateArrival`, `formatEtaCountdown`) compute an estimated arrival timestamp and render it as text; `renderLockPanel` swaps in an ETA span instead of "time ago" for the direction that heads toward OVRC at each lock; a new 30-second `setInterval` re-renders just that span's text so the countdown ticks live without re-fetching data.

**Tech Stack:** Vanilla JS in `index.html` (no framework, no new dependencies, no test harness for this file — verified manually in a browser per existing precedent for this file's other pure helpers).

**Reference spec:** `docs/superpowers/specs/2026-08-26-lock-eta-design.md`

In `index.html`, insert this immediately after `const LOCK_KEYS = ['belleville', 'willowIsland'];` (and before `function timeAgo(date) {`):

```js
// Rough, not-required-to-be-accurate estimate — 8 mph is a round-number
// typical towboat cruising speed, not measured data.
const ASSUMED_TOW_SPEED_MPS = 8 * 0.44704;

// Only this direction, per lock, heads toward OVRC (matches approachSource()'s
// existing convention for live AIS vessels).
const LOCK_APPROACH_DIRECTION = { belleville: 'U', willowIsland: 'D' };

const LOCK_DISTANCE_M = {
  belleville: distanceM(BELLEVILLE, OVRC),
  willowIsland: distanceM(WILLOW_ISLAND, OVRC),
};

function estimateArrival(lockageIso, distanceMeters, speedMps) {
  return Date.parse(lockageIso) + (distanceMeters / speedMps) * 1000;
}

function formatEtaCountdown(arrivalMs, nowMs) {
  const remainingMs = arrivalMs - nowMs;

  if (remainingMs >= 60_000) {
    const totalMins = Math.round(remainingMs / 60_000);
    const hours = Math.floor(totalMins / 60);
    const mins = totalMins % 60;
    return hours > 0
      ? `ETA ${hours}h${mins > 0 ? ' ' + mins + 'm' : ''}`
      : `ETA ${mins}m`;
  }

  if (remainingMs > -60_000) {
    return 'ETA arriving now';
  }

  const totalMins = Math.round(-remainingMs / 60_000);
  const hours = Math.floor(totalMins / 60);
  const mins = totalMins % 60;
  return hours > 0 ? `Passed ~${hours}h ago` : `Passed ~${mins}m ago`;
}
```

`hours` and `mins` are derived from a single rounded total-minutes value rather than rounded independently — computing them separately (`Math.floor(ms/3_600_000)` for hours, `Math.round(remainder/60_000)` for minutes) lets the two disagree right at an hour boundary: at 59.5–60 minutes remaining, independent rounding produces `hours=0, mins=60` — rendering the nonsensical `ETA 60m` instead of `ETA 1h`. Deriving both from one rounded total avoids that.

Note the parameter is named `distanceMeters`, not `distanceM` — `distanceM` is already the name of the existing haversine-distance function defined later in this same script (`function distanceM(a, b) {...}`, function declarations are hoisted so calling it earlier in the file is safe), and reusing that name as a parameter would shadow it confusingly.

```bash
node -e "
const fs = require('fs');

// Same haversine implementation and real coordinates as index.html, so this
// fixture's assumed distance is bit-for-bit identical to what the app itself
// computes — no drift between the fixture's target minutes and what renders.
function distanceM(a, b) {
  const R = 6371000;
  const dLat = (b[0] - a[0]) * Math.PI / 180;
  const dLon = (b[1] - a[1]) * Math.PI / 180;
  const lat1 = a[0] * Math.PI / 180;
  const lat2 = b[0] * Math.PI / 180;
  const x = Math.sin(dLat / 2) ** 2 + Math.cos(lat1) * Math.cos(lat2) * Math.sin(dLon / 2) ** 2;
  return R * 2 * Math.atan2(Math.sqrt(x), Math.sqrt(1 - x));
}
const OVRC = [39.2833, -81.5631];
const BELLEVILLE = [39.1193, -81.7425];

const ASSUMED_TOW_SPEED_MPS = 8 * 0.44704;
const distanceMeters = distanceM(BELLEVILLE, OVRC);

// lockageAgeMinutes chosen so (transit time - age) lands in each target bucket
const transitMin = (distanceMeters / ASSUMED_TOW_SPEED_MPS) / 60;

function lockageTimeFor(remainingMinutesTarget) {
  const ageMinutes = transitMin - remainingMinutesTarget;
  return new Date(Date.now() - ageMinutes * 60000).toISOString();
}

const output = {
  updated: new Date().toISOString(),
  locks: {
    belleville: {
      name: 'Belleville Locks and Dam',
      recentLockages: [
        { vesselName: 'ETA TEST SOON',    direction: 'U', numBarges: 11, endOfLockage: lockageTimeFor(8),   mmsi: 1 },
        { vesselName: 'ETA TEST ARRIVING', direction: 'U', numBarges: 9,  endOfLockage: lockageTimeFor(0.2), mmsi: 2 },
        { vesselName: 'ETA TEST PASSED',   direction: 'U', numBarges: 6,  endOfLockage: lockageTimeFor(-10), mmsi: 3 },
        { vesselName: 'AWAY FROM OVRC',    direction: 'D', numBarges: 14, endOfLockage: lockageTimeFor(8),   mmsi: 4 }
      ]
    },
    willowIsland: {
      name: 'Willow Island Locks and Dam',
      recentLockages: []
    }
  }
};

fs.writeFileSync('/tmp/lock-eta-test-server/lock-traffic.json', JSON.stringify(output, null, 2));
console.log('transit minutes for this fixture distance:', transitMin.toFixed(1));
"
```
